# NOVA Genesis

A premium **Electron-only desktop AI operating system** — an original assistant
inspired by the responsiveness, elegance, and natural interaction of cinematic
AI companions. Everything executes as a native desktop application inside
Electron: **no browser UI, no localhost server, no web dashboard.**

## Architecture

```
Electron Main ── NOVA Core (orchestrator)
 ├── Tool Registry / Builder / Validator / Executor (worker process)
 ├── AI Provider Registry  (Gemini Live voice + Grok reasoning, swappable)
 ├── Semantic Memory Engine (embeddings, decay, dual-source retrieval)
 ├── Windows Integration (clipboard, notifications, shortcuts, launching)
 ├── Python Backend (persistent JSON-RPC worker: OCR, automation, filesystem)
 ├── Secret Store (OS-encrypted vault), IPC firewall, audit logger
 └── Renderer (bundled React HUD shell, sandboxed, offline)
```

- **Gemini Live** owns voice conversation, streaming audio, and natural
  interaction.
- **Grok** owns reasoning, planning, software engineering, and tool synthesis —
  routed by the intent classifier in `task_router.ts`.
- **Tool Builder** synthesizes missing capabilities (provider-agnostic, with a
  deterministic local fallback), validates them statically, runs them in a
  sandboxed **worker process** under a hard wall-clock kill, and registers them
  with full metadata, versioning, rollback, and an execution ledger.
- **Python backend** (`python/nova_runtime`) runs as a persistent asyncio
  JSON-RPC worker over stdio with sandboxed filesystem, OCR, and automation
  services, honest capability gating, and automatic restart with backoff.

See `docs/NOVA_ARCHITECTURE.md` for the full design, `docs/BUILD_WINDOWS.md`
for Windows build/package instructions, and `docs/PHASE1_2_IMPLEMENTATION_REPORT.md`
for the implementation history and audit evidence.

## Requirements

- Node.js >= 18.17, npm
- Electron >= 28 (installed as a dev dependency)
- Python 3.10+ (optional but recommended — powers OCR/automation tooling;
  without it those tools report availability honestly and degrade gracefully)
- Windows 10/11 for full native integration (clipboard, notifications,
  ffmpeg audio capture, global shortcuts)

## Getting started

```bash
npm install          # installs dependencies, rebuilds native modules (postinstall)
npm run build        # typecheck + compile main + bundle renderer
npm run dev:dual     # run Vite renderer + Electron main with live reload
npm run test:unit    # headless unit tests (requires build first)
npm run e2e:smoke    # end-to-end smoke test
```

Configure API keys in a `.env` file at the repository root (or via the secret
vault at first run):

```
GEMINI_API_KEY=...
GROK_API_KEY=...
PICOVOICE_ACCESS_KEY=...
```

## Configuration

All tunables live in `src/main/core/config.ts`, overridable via environment
variables: `NOVA_PROVIDER_PRIORITY`, `NOVA_SANDBOX_MEMORY_MB`,
`NOVA_TOOL_TIMEOUT_MS`, `NOVA_TOOL_WORKER`, `NOVA_TOOL_WORKER_GRACE_MS`,
`NOVA_CONTROL_HOSTS`, `NOVA_CONTROL_PORTS`, `NOVA_PYTHON_PACKAGE`,
`NOVA_PYTHON_ROOTS`, `NOVA_PYTHON_TIMEOUT_MS`, `NOVA_CONTEXT_POLL_MS`, and more.

## Security model

- API keys live in an OS-encrypted vault (`safeStorage`); they are **never**
  written to child-process environments — every `spawn()` receives an explicit
  scrubbed environment.
- Generated tools run in a dedicated worker process with no host APIs, a
  memory cap, and a hard wall-clock kill; static AST auditing and permission
  enforcement provide defense in depth.
- Renderer is sandboxed (`sandbox: true`, `contextIsolation: true`), IPC is
  firewalled and PII-sanitized, network control builtins are host/port
  allowlisted, and every security-relevant action is audited.

## Packaging (Windows)

```bash
npm run electron:package
```

Produces an NSIS installer and portable executable via electron-builder
(config in `package.json` → `build`). Icon assets are generated by
`scripts/generate-icon.js` into `build/`.

## Testing

- `npm run test:unit` — 62 headless tests covering the registry, validator,
  executor (including the hard wall-clock kill of a runaway loop and worker
  respawn), builder, task router, memory engine, permission enforcement,
  execution ledger, and the live Python worker protocol.
- `npm run e2e:smoke` — Electron smoke test.
- `npx eslint src scripts` — lint.
- `cd python && python -m py_compile $(find . -name '*.py')` — Python syntax.
